Chaos Ratio: luck or a fixable trap?

Each run is replayed with one drop nudged by 0.0001 units, far below a pixel. If the outcome flips as often as a fresh coin toss would, losses are dice rolls (C ≈ 1). If it never flips, losses are reproducible traps a designer can fix (C ≈ 0). Pass rate alone can't tell these apart. Measured for the regular bot: a different play style can score the same level differently.

Twist exposure: do the bots even experience the level's twist?

Each run is paired with a copy where one twist is switched off (same seeds). Identical pairs mean the twist never touched that run. Fast bots finish time-based levels before the twist arrives, so they report a level is fine without ever seeing its point.

The patch

For every off-target level the agent played one batch with unlimited drops and read the pass rate for every possible drop limit off the survival curve, picked the limit that hits the target, then verified it with fresh seeds.

Method

    
The real game code (unmodified) is bundled and run headless with a virtual clock: no rendering, a seeded random stream per run, and leaked state reset between runs, so the same seed replays byte for byte. Bots act every  s, the speed of a human player. Pass rates carry Wilson 95% intervals. The Chaos Ratio is flip rate ÷ 2p(1−p) over paired replays. Targets: a regular player passes 95% of level 1 falling linearly to 60% on level 20, ±10 points.
